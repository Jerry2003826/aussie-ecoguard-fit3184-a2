## 产品定位与成功标准

Aussie EcoGuard 帮助用户把动物照片和视频转成可以检索、整理、订阅的目击记录，并帮助宠物主人查找疑似走失宠物。主要价值是减少人工整理和查找成本，让识别结果、原始媒体和目击时间能够连起来使用。

| 用户 | 要完成的事情 | 成功表现 |
| --- | --- | --- |
| 动物目击上传者 | 上传照片或视频，自动整理后查看与校正结果 | 文件不丢失，处理状态清楚，标签和数量可解释 |
| 宠物主人 | 用照片、颜色、品种和时间范围查找公开目击 | 得到可打开的疑似匹配及依据，无匹配时知道下一步怎么调整 |
| 研究者或巡护人员 | 查询特定物种和数量，订阅新增记录 | 多条件查询正确，通知仅包含可访问的匹配记录 |
| 四人项目团队与考官 | 重现系统行为，理解设计与成员贡献 | 环境可访问，流程可重复，报告、代码和演示一致 |

完成标准同时包括：全部评分功能、完整网页、真实 AWS 与 GCP 通信、真实邮件和 Lex、权限与隐私验证、部署与恢复说明、报告材料、全员演练。功能实现、云端验证和人工验收分别记录，不用其中一项替代另外两项。

## 用户流程与页面规划

网站以“我的媒体”“搜索”“寻找宠物”“订阅”作为主要入口，聊天助手在业务页面内可打开。登录后优先呈现图库与明确的上传按钮，不设置空洞的统计首页。

| 页面或组件 | 主要操作 | 必须呈现的状态 |
| --- | --- | --- |
| 认证页面 | 注册、邮箱验证、登录、临时密码改密、退出；提供密码找回 | 邮件已发送、验证失败或过期、密码错误、会话过期 |
| 我的媒体 | 图片和视频上传、多选、查看处理状态、管理自己的文件 | 上传进度、排队、处理中、已完成、重复、失败与重试 |
| 媒体详情 | 原图或视频、标签、检测数量、模型版本、目击时间、可见性、编辑与删除 | 不存在、无权限、链接失效后刷新、删除中 |
| 综合搜索 | 物种、最低数量、AND 组合、缩略图反查、上传文件搜索 | 查询中、匹配结果、明确空结果、验证错误、后端失败 |
| 寻找宠物 | 宠物图片或描述、时间范围；查看疑似目击 | 输入不完整、无法识别、候选结果、匹配依据和无结果提示 |
| 订阅设置 | 选择标签、确认邮箱、查看与取消订阅 | 待确认、已启用、发送异常、取消成功 |
| Lex 聊天组件 | 用自然语言查动物、数量、日期或寻找宠物 | 正在处理、追问、可点击媒体、无法理解、服务失败与重试 |

核心流程 A：注册与验证 → 登录 → 上传 → 看到处理状态 → 自动识别与整理 → 查看媒体详情 → 校正标签 → 再次搜索。

核心流程 B：登录 → 上传宠物查询照片或填写描述 → 选择近期范围 → 查看公开疑似目击 → 打开原图或视频。查询素材不进入普通媒体库。

核心流程 C：确认标签订阅 → 出现可访问的匹配上传或更新 → 收到邮件 → 登录后打开媒体。

核心流程 D：输入“Show me photos of foxes spotted yesterday” → Lex 识别物种与日期 → 调用真实查询 → 返回可点击结果；缺信息则追问。

## 功能规格与业务规则

以下具体规则是本项目的产品决策基线。作业明确规定的项会直接标明；其余数值与语义可以在 G0 样本验证后调整，但应先更新验收清单。

### 认证与可见性

必须使用 AWS Cognito。注册保存邮箱、名、姓，密码由 Cognito 管理。邮箱验证与临时密码首次修改分别设计和测试；邀请账号的临时密码路径有独立的首次登录挑战，不能用普通登录替代。[AWS Cognito 账号创建说明](https://docs.aws.amazon.com/cognito/latest/developerguide/how-to-create-user-accounts.html)

未登录者可访问认证及必要验证页面，不能访问业务页面或 API。API 返回明确的认证或授权错误，不用登录页 HTML 代替 API 错误。会话过期后提示重新登录，并尽可能保留尚未提交的筛选条件。

媒体默认私有；用户明确选择公开后，作为平台内所有已登录用户可搜索的公开目击。别人可以查看公开记录，但不能编辑或删除。公开不等于匿名开放，也不涉及外部网络搜索。读取、检索、缩略图、聊天结果、邮件和直接下载都执行同一套权限。

### 上传与自动处理

首版建议支持 JPEG、PNG、WebP 图片和 MP4 视频；初始上限为单图 20 MB、视频 100 MB 且不超过 120 秒、每批最多 10 个文件。它们是控制演示成本与处理时长的初始限制，并非 PDF 规定；G0 检查素材和处理能力后冻结。

状态为：上传中 → 等待处理 → 处理中 → 可查询；另有重复、处理失败、删除中。上传成功不等于识别完成。失败显示可理解的原因与重试操作，不要求用户手工刷新。

以同一用户的原始文件内容 SHA-256 去重，服务端验证内容校验。相同内容改名仍视为重复，同名不同内容允许上传，不同压缩版本不视为同文件。并发上传相同文件只能形成一个有效记录；跨用户响应不得泄露私人媒体是否存在。

上传事件触发缩略图和识别处理；图片保持比例并压缩，原文件不被覆盖。自动整理为宠物、入侵物种、混合或待确认等分类，并记录最终对象位置。实际移动或复制对象时避免再次触发同一处理链，也要保持文件身份与查询引用一致。未发现动物属于处理完成但无标签，不属于系统故障。

### 视频与数量

作业硬要求是每 10 秒抽一帧。采样时间点定为 0、10、20 秒等且小于视频时长；不足 10 秒取首帧。24 秒视频应得到 0、10、20 秒三个采样点。

视频物种标签取采样结果并集；某物种数量采用各采样帧中的最大同时可见数量，避免跨帧重复累加。视频 AND 查询按整段记录判断，不要求不同物种出现在同一帧。界面说明这是采样估计，不能表示整段视频独立动物总数。若教学团队后续明确其他语义，统一修改处理、查询、界面与文档。

### 自动标签与人工编辑

入口识别模型必须属于 MegaDetector、Ultralytics YOLO 或 AWS Rekognition，可接合规的后续模型；无需训练或微调。先验证猫、狗、狐狸、野猪、蟾蜍、多只动物和无动物素材，再决定模型组合。

自动结果保留物种、数量、置信度和模型版本。不得把猫直接当作野猫、把猪直接当作野猪；无法判断的品种或特征应保留不确定性。兼容模型版本通过配置和模型文件更换，业务代码及 Lambda 源码无需改动；更换完全不同的输入输出格式仍属于适配工作，不能承诺任意模型零代码切换。

人工标签必须区分来源。描述标签不增加动物数量；人工补充物种标签可表示至少存在 1 只，并清楚标记为人工确认，不能据此声称模型识别出精确数量。重复添加不累加，删除不存在标签直接忽略；被移除的标签不继续参与有效查询。

### 查询与走失宠物

物种和最低数量条件均按 AND 执行；例如至少 1 只野猪且至少 3 只蟾蜍，两个条件都满足才返回。图库支持分页；无匹配显示空结果，服务失败显示错误。

缩略图反查只处理系统已知的媒体链接，不抓取任意外部 URL。媒体使用稳定身份，展示用的下载链接过期后可以刷新，不影响标签编辑、删除与反查。

以图片或视频搜索时，识别全部有效物种标签并对已有记录进行 AND 查询。查询素材走独立临时处理路径，不写媒体索引、不触发通知，成功、失败、取消或超时后清理。没有识别到物种时提示调整输入，不能把空条件解释成返回全库。

寻找宠物同时支持图片和描述。默认最近 30 天，可调整范围；优先用目击时间，缺失时明确采用上传时间。统一以 UTC 存储，展示和“昨天”等相对日期按选定用户时区解释。先过滤公开、时间和物种，再结合颜色、可判断的品种与图片特征排序。结果展示“疑似匹配”及依据，不宣称已经确认同一只动物。

### 批量操作与删除

批量标签接口遵守 URL 列表、标签列表及 operation 为 1 或 0 的格式。参数错误或包含无权管理的文件时，先拒绝本次请求并说明原因；业务操作中的部分运行失败则逐文件报告，并提供失败项重试。

删除先从搜索中隐藏记录，清理原媒体、缩略图、视频抽帧、相似度特征和相关数据库记录，全部成功后才显示删除完成。存储和数据库不存在天然共同事务，需要可重试的状态机制实现一致性。已删除对象重复删除应安全，不将“已接收删除请求”等同于全部清理完成。

### 标签邮件与聊天

邮件订阅须经邮箱确认；匹配上传或有效更新才触发，事件重试和无效编辑不能重复轰炸。私有记录只允许其所有者相关订阅收到通知；其他用户仅能收到公开内容通知。邮件链接要求登录，取消订阅后停止发送。

AWS Lex 必须是真实对话入口，并调用真实的服务端查询。支持物种、数量、颜色、日期和寻宠意图；缺少条件时追问，无法理解时展示支持的问法。聊天与普通查询使用相同权限和搜索逻辑。

## 双云职责与系统依赖

建议采用一套主要业务后端，由第二个云承担真实模型推理职责，减少重复建设。此方案在 G0 的账号权限与模型测试通过后冻结。

| 系统职责 | 候选服务与实现 | 选型目的 |
| --- | --- | --- |
| 用户认证 | AWS Cognito | 满足硬性要求，集中管理用户与令牌 |
| 业务 API | AWS API Gateway 与 Lambda | 处理鉴权、上传授权、查询和文件管理 |
| 原媒体与缩略图 | AWS S3 | 事件触发、媒体存储及受控访问 |
| 异步处理 | S3 事件、SQS 与 Lambda 或适合处理时长的服务编排 | 分离上传与识别，处理重试和失败队列 |
| 媒体与订阅索引 | AWS DynamoDB | 保存稳定媒体标识、标签数量、归属、状态和模型版本 |
| 动物识别与图片特征 | GCP Cloud Run 的模型服务 | 第二云执行核心工作，适合按请求运行模型容器 |
| 模型和配置资源 | GCP Cloud Storage 与 Artifact Registry | 管理模型版本、配置与部署镜像 |
| 自然语言查询 | AWS Lex V2 与 Lambda | 满足指定聊天能力，复用搜索业务逻辑 |
| 标签通知 | AWS SNS 等受支持的无服务器邮件路径 | 按订阅匹配发送通知，验收真实邮件 |
| 前端 | React 与 TypeScript，静态托管方案随 AWS 权限确定 | 覆盖完整网页和可维护的组件 |
| 服务端实现 | Python 媒体与模型处理；声明式部署脚本 | 便于处理图片、视频、SDK 和可复现部署 |

跨云链路为：受控上传 → AWS 事件任务与媒体预处理 → GCP 模型服务 → AWS 索引更新 → 网页、搜索、通知和 Lex 读取相同结果。详细实施方案将抽帧与入口识别放在 AWS worker，补充检测与图片特征放在 GCP；模型组合和处理时限通过 G0 实测后冻结。

跨云服务身份优先验证 Workload Identity Federation，用 AWS 临时角色凭证换取短期 GCP 凭证，避免持久服务账号密钥；实际 LabRole、GCP 授权以及 Cloud Run 调用仍需现场验证。[Google 跨云身份联合说明](https://docs.cloud.google.com/iam/docs/workload-identity-federation-with-other-clouds)

用户发起的跨云查询保留并验证 Cognito 身份上下文，异步任务使用已验证的媒体归属及受信任服务身份。机器身份不能替代用户数据权限。部署运行不依赖开发者手工复制的 Learner Lab CLI 临时密钥。

正式报告中的多云架构图必须使用厂商官方图标，并标明用户身份、服务身份、数据流、事件和存储边界。上表是职责方案，不能代替正式架构图。

先冻结接口、状态和权限规则，再分别实现前端与处理模块，减少后续整合返工。

| 核心实体 | 最少保存的信息 |

| 检测结果 | 媒体 ID、物种、数量、置信度、采样时间、模型版本、自动或人工来源 |

| 查询临时素材 | 临时任务 ID、请求用户、清理状态和到期时间；不得成为媒体库记录 |

测试分为三层：确定输入下的业务逻辑、真实推理对人工标注的模型效果、真实双云端到端流程。模型正确性不能靠人工修改标签证明；查询正确性不能靠模型偶然给出正确标签证明。

首轮模型门槛先检查每种关键物种是否有可重复成功的真实样本、数量逻辑是否可靠；达不到就调整合规模型链，不通过挑选个别成功截图宣布通用能力。随后基于固定验证集记录精确率、召回情况、数量误差和寻宠候选质量，在 G0 冻结内部阈值。

内部体验目标：页面提交操作后约 1 秒内显示等待或进度反馈；小规模演示数据集的非模型查询，预热后 P95 目标 3 秒以内；图片处理目标 60 秒以内，120 秒上限视频目标 5 分钟以内。它们受样本、模型、冷启动和网络影响，G0 性能试验后确认或调整。所有异步任务必须有可查询状态，超时不得永久转圈。

Beta 门槛是全部评分功能在真实环境至少完整走通一次。发布验收门槛是安全、隐私、异常与完整流程通过；不存在阻断演示、越权、数据丢失或残留查询素材的缺陷；已知小问题有记录和处理意见。

缺陷优先级：P0 为越权、凭证泄漏、数据丢失或主流程完全不可用；P1 为任一评分功能失效、常用流程错误或关键通知失败；P2 为有替代操作的体验缺陷。发布前 P0 与 P1 清零。

### 默认实现与技术边界

前端采用 React、TypeScript 与 Vite；AWS API 使用 Python Lambda 和 API Gateway HTTP API；共享业务逻辑放在普通 Python 模块中，避免把规则散落在各个云函数。GCP 推理服务采用 Python、FastAPI 与固定版本模型依赖，封装为容器；AWS 媒体预处理容器包含 FFmpeg。Python 以 3.12 兼容性为首轮验证基线；Node、依赖、基础镜像和模型权重在 E01 与 E04 通过后锁版本和摘要，不使用浮动 latest 作为发布依据。

基础设施默认使用 Terraform，AWS 与 GCP 分开状态文件，配置通过输出交换。先检查课程账号能否管理所需资源；若某服务只能控制台创建，就保留完整参数、资源 ID 和导入步骤，不反复尝试权限明确禁止的操作。状态文件含敏感信息，应放在限制访问的位置并排除 Git。

业务媒体保存在私有 S3；GCP Cloud Storage 保存模型与配置；DynamoDB 保存媒体、去重、任务、查询索引、订阅、通知和聊天会话。首版只建一个可验收的 dev 环境，在通过后冻结为 demo，避免同时运行两套付费推理资源。

前端静态托管首选 S3 私有桶加 CloudFront OAC；若课程权限不可用，则使用独立 Cloud Run Web 容器承载前端静态文件。登录入口和静态应用资源可以公开加载，业务路由先完成身份检查，全部业务数据接口保持鉴权。模型 Cloud Run 服务保持 IAM 保护，不与公开 Web 服务混用服务账号或权限。

普通 API 只传 JSON 与对象引用；文件通过短期预签名授权直传 S3。浏览器发起处理后立即获得任务 ID 并轮询状态，视频推理不占用浏览器的业务 API 请求。HTTP API 的集成最长 30 秒且载荷有限，不能把大视频正文或整个推理时间放进该入口。[API Gateway HTTP API 配额](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-quotas.html)

首版视频采用 SQS → Lambda worker → Cloud Run 请求 → Lambda 写回。应用处理期限初设 330 秒，Cloud Run 请求超时 360 秒，调用方总期限 390 秒，Lambda 超时 480 秒，SQS 可见性超时 2880 秒；每批 1 条任务、worker 并发 2、Cloud Run 最大实例数 2、每实例并发 1。它们是保护值，E04 实测后调整；最长 120 秒的视频只有至多 12 个采样点。如果模型无法在此预算内稳定完成，必须切换作业式执行并重新验收，再进入完整开发。

处理器必须主动取消到期推理和 FFmpeg 子进程。Cloud Run 平台返回超时不代表容器中的代码已停止，因此重试前要核对任务状态，防止原任务仍在运行。[Cloud Run 超时行为](https://docs.cloud.google.com/run/docs/configuring/request-timeout)

后台不使用电脑上手工复制的 AWS 临时密钥。AWS Lambda 使用执行角色自动取得凭证，经 Workload Identity Federation 换取 GCP 短期身份；调用 Cloud Run 所需的是正确 audience 的 Google ID token，不能把普通 Google access token 当作调用凭证。此路径须由 E03 真实验证。

### 身份传递与权限实现

Cognito 创建 User Pool 和无客户端密钥的浏览器 App Client；自助注册启用邮箱验证，保存 given_name 与 family_name。React 用 Cognito 官方 SDK 支持的流程处理注册、确认、登录、临时密码挑战、找回密码和退出；不在应用服务器保存密码。

API Gateway JWT authorizer 校验 issuer、client_id 或 audience、签名和有效期；业务中间件再明确限制 token_use 为 access，并从已验证的 sub 派生当前用户。若采用自定义 OAuth scopes，必须通过能签发这些 scopes 的登录路径测试；不能只改 API 配置就假定原生登录 token 带有所需 scope。[HTTP API JWT authorizer](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-jwt-authorizer.html)

跨云同时区分用户身份与服务身份。至少建立一条真实用户查询授权链路：受保护的查询任务创建 API 把 Cognito access token 转发到 Cloud Run 的轻量 `POST /v1/query-authorizations`，第二云验证 JWKS 签名、issuer、client_id、token_use、expiry 与请求用途，返回可信 sub 和请求关联 ID；AWS 确认身份一致后建立查询任务。这个端点懒加载模型，调用预算不超过 8 秒，失败返回可重试错误，不静默跳过第二云检查。

调用时 `X-Serverless-Authorization` 携带 Google ID token，`Authorization` 携带 Cognito access token；两种 token 分别由 Cloud Run IAM 和应用验证。后台 `/v1/infer`、`/v1/embed` 只接受允许的服务身份与服务端生成的任务上下文，不要求用户 token 等待视频完成，也不把原始 token 写入队列或数据库。[Cloud Run 服务间身份验证](https://docs.cloud.google.com/run/docs/authenticating/service-to-service)

不得采信前端提交的 ownerId、email、userId 或 bucket。创建任务与上传授权使用服务端身份；所有媒体查询、下载授权、标签修改、删除、通知和 Lex fulfillment 复用同一个 `can_read / can_edit` 权限模块。私有媒体仅所有者可读；公开媒体仅登录用户可读；所有写操作仅所有者可执行。

云 IAM 优先使用分别承担 API、worker、通知和删除的最小权限角色；若 Learner Lab 仅允许使用预置 LabRole，记录实际受限情况和补充的桶策略、队列策略及应用检查，不把共享宽权限角色描述成已实现理想的职责隔离。WIF 至少限制 AWS 账号和角色；能够使用专用角色时再缩小到专用角色。

### 模型与媒体处理的具体方案

E04 首先验证的候选链是 AWS Rekognition → GCP Grounding DINO Tiny → SigLIP2 Base。Rekognition 是作业指定的入口，结果必须参与动物标签和检测判断；Grounding DINO 补充狐狸、野猪、蟾蜍等目标框与计数，SigLIP2 负责图片及描述向量匹配。后两者的所选官方模型卡标注 Apache 2.0；下载前仍记录各个权重 revision、许可及依赖许可。这个组合是待基准验证的首选，不代表已证明能准确识别所有目标物种。[Rekognition 标签与框](https://docs.aws.amazon.com/rekognition/latest/dg/labels.html) [Grounding DINO Tiny 模型卡](https://huggingface.co/IDEA-Research/grounding-dino-tiny) [SigLIP2 Base 模型卡](https://huggingface.co/google/siglip2-base-patch16-256)

媒体预处理放在 AWS worker 的轻量容器中：下载本次授权对象，验证真实类型、大小和视频时长，用 Pillow 或 FFmpeg 生成缩略图及 JPEG 采样帧，再调用 Rekognition。WebP 先规范化为 JPEG 或 PNG，视频按 0、10、20 秒抽帧；不能把视频字节直接交给图片识别 API。输出到 `derived/<mediaId>/<generation>/`，与上传事件前缀隔离。

推理协调 worker 再把帧的短期读取 URL、入口模型结果、taxonomy 和固定 manifest 版本交给 GCP。Cloud Run 输出统一的检测、每帧数量、宠物裁剪特征和模型版本；只返回 JSON 或指定结果对象引用，禁止无上限的大型响应。多模型的相同目标按框重叠和规范标签去重，不能把两个模型的数量相加。

GCP 首轮以 4 vCPU、8 GiB、单实例并发 1 作为测量起点，最小实例为 0；记录冷启动、逐帧和整批耗时。实例规格是工程初值，不是模型官方最低配置。先测 CPU；只有 CPU 不满足预算且你接受费用后才考虑 GPU。模型权重放 GCS，服务账号只能读取指定模型路径。

`config/model.example.json` 定义 detector、embedding model、不可变 revision、权重 SHA-256、词汇表、阈值、预处理版本、schemaVersion 和回退版本。任务创建时固定 manifestVersion，处理中不混用新旧版本。兼容权重切换只改 manifest 并受控重载服务；向量模型版本变化时重建对应特征，禁止直接比较不同版本的向量。

普通文件搜索只按识别的物种 AND 查询；寻宠照片使用同版模型产生的宠物裁剪向量。先按公开状态、时间与物种过滤，再按归一化向量余弦相似度排序；文字描述使用同一模型的文本向量，结构化颜色和品种只在有可靠依据时参与。相同媒体的多个宠物或视频帧取最高有效匹配分数，结果按媒体去重，展示 Top 10 疑似结果和依据；低分无匹配不能强行返回“找到”。

E04 先用约 30 份人工标注素材验证可行性，至少覆盖每个目标物种的单只、多只、混合、相似负例和无动物画面。完整验收扩大到至少 50 份未用于调阈值的素材，并包含同宠不同照片、同种不同个体的寻宠组。报告每类 precision、recall、计数准确率、寻宠 Top 5 命中及失败样例。冻结门槛时依据样本结果给出具体数值与样本量，不能只写“看起来不错”。课程明确的查询案例必须有真实识别证据，逻辑测试种子数据不能冒充模型能力。

如果 Rekognition 权限不可用或目标类别失败，先试作业允许的其他入口与预训练补充分类器。MegaDetector 只给 animal、person、vehicle 等检测，不能直接当作物种分类；YOLO 普通 COCO 权重也不覆盖所有作业物种。使用 YOLO World 候选前核对模型许可、课程私有仓库安排和真实样本结果。每条候选路线最多安排一次短期基准比较，10 月 9 日前选定可交付路径；没有合格路径时将其作为阻塞，而不是用人工补标签掩盖自动识别缺失。

### 数据模型和一致性规则

采用少量明确职责的 DynamoDB 表。字段名在 `contracts` 冻结，数据库记录保存稳定对象身份，签名 URL 只在需要访问时生成。

| 表 | 主键与主要内容 | 必须支持的操作 |
| --- | --- | --- |
| Media | mediaId；ownerSub、visibility、status、sha256、object refs、tags、counts、timestamps、modelVersion、recordVersion、generation | 按 ID 强一致读取与条件更新；所有业务权限最终回查 |
| SearchIndex | scopeSpecies 为分区，observedAt 与 mediaId 为排序；scope 为用户私有或全站已登录可见的公开范围 | 按物种和时间查询候选；标签和可见性改变时更新 |
| Operations | 类型前缀加 ID；上传、去重占位、处理、查询、删除、会话及短期游标 | owner 加 checksum 条件占位；任务状态、尝试、租约和过期清理 |
| Subscriptions | ownerSub 与订阅 ID；规范标签、启用状态、SNS 主题与确认状态 | 按用户读取；按标签索引筛选订阅候选 |
| Outbox | eventId；实体 ID、版本、事件类型、投递状态、重试信息 | 与业务提交同事务写事件，后续投递队列或通知 |

媒体对象字段包括 originalRef、thumbnailRef、derivedRefs、featureRef 和 knownUrlAliases，引用保存 bucket、key 及需要的 versionId。embedding 大对象存私有派生文件，DB 保存位置与 featureVersion；任何单条记录和 API 返回都设置大小上限。

有效标签计算为自动标签加人工新增，再减人工移除；计数分别保存自动数量和人工确认的最低数量。标签规范化使用 `config/taxonomy.json`，例如界面“feral pig”映射为 `feral_pig`，API 对约定的显示名称提供兼容解析。每次有效修改增加 recordVersion；重复添加或移除不存在项不增加版本，也不产生通知。

SearchIndex 只负责找到候选，不承担最后的权限判断。先查询一个合适的物种分区，再对 Media 中当前有效数量做全部 AND 检查；同时查询用户私有与公开范围并去重。分页必须继续读取候选直到结果页填满或候选耗尽，不能仅过滤第一批候选后错误宣称没有更多结果。游标为短期不透明 ID，绑定用户、过滤条件和查询进度，不能跨用户复用。

Outbox 解决“数据库已写好、消息未成功入队”的中断：更新 Media 和写待投递事件放在同一 DynamoDB 事务；投递器失败可重试，下游根据 eventId 去重。它不能把 S3 操作也变成事务。所有 API 与 worker 共享同一事件 schema，测试中要主动制造提交后投递前的失败。[DynamoDB 事务范围](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/transaction-apis.html)

上传按 ownerSub 加 SHA-256 条件占位，只有首次成功的会话成为有效媒体；未上传、校验失败或超时占位可安全回收。浏览器计算 checksum，预签名 SigV4 请求绑定 SHA-256，S3 校验实际内容，worker 再核对上传会话、校验值、大小与类型；ETag 不作为通用 SHA-256。[S3 上传校验与预签名](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)

删除增加 generation 并置 DELETING，从读和搜索中立即隐藏。迟到的推理、手动重试或旧通知写回必须检查 generation、attemptId 与当前状态，不能恢复已删除记录。删除 worker 依据完整对象清单清理原件、缩略图、帧、特征、索引、去重关联和用户数据记录；如桶启用版本控制，连同对应旧版本与删除标记一起处理。仅保留不含媒体内容的限期操作凭据，阻止旧事件复活，并在保留期后清理。

### 上传与查询的状态流转

上传流程为 `UPLOADING → QUEUED → PREPROCESSING → INFERRING → READY`，另有 `DUPLICATE / FAILED / DELETING`。查询素材使用独立 `QUERY_UPLOADING → QUERY_QUEUED → QUERY_RUNNING → QUERY_READY → CLEANED` 状态，不创建 Media 或 SearchIndex 项；失败同样进入清理步骤。

1. API 先建立上传会话并签发指定对象的上传 URL；客户端上传到 `incoming/library/<uploadId>` 或 `incoming/query/<queryId>`。上传 URL 不复用其他人的 key。

2. S3 事件投递同区域 Standard SQS；事件前缀仅匹配 incoming。客户端 complete 调用用于确认和恢复状态，自动处理仍由事件推进。二者到达顺序不同也应得到相同结果。

3. 预处理 worker 校验真实对象并生成缩略图、帧和入口模型结果，通过 Outbox 安排推理任务。模型协调 worker 将结果规范化，再条件提交媒体状态、索引和通知事件。

4. 重复和乱序事件按 uploadId、对象版本及 generation 去重。只重试可恢复的网络、429 或部分 5xx；非法文件、超长视频、确定性模型错误及时写 FAILED 并确认消息，不让 UI 一直等待 DLQ。

5. 每次尝试的本地临时目录都用 finally 清理；云端查询输入、帧和向量在成功、取消、永久失败或总期限到达时立即删除。可恢复失败保留素材供本任务下一次尝试，不能在第一次网络错误后删掉重试输入。query 总期限初始为创建后 15 分钟，Operations 保存 expiry、租约和 attemptId；每 5 分钟的清理器先终止过期任务，再清理云端对象，不能误删有效租约内的素材。只保留短期结果 ID 与非图片诊断，不保存可恢复原图的特征。存储生命周期和 DynamoDB TTL 仅作为兜底，不能声称 TTL 会立即删除。

6. 用户断网不等于服务器停止；重新进入页面按任务 ID 恢复状态。取消查询先标记取消并阻止发布结果，后台完成清理后显示取消完成。

S3 通知按至少一次交付设计，不能依赖固定顺序或只收到一次。原始对象归档到 `library/<classification>/<ownerSub>/<mediaId>/` 后更新稳定引用，派生文件与归档复制不得再次触发原始识别。[S3 事件通知](https://docs.aws.amazon.com/AmazonS3/latest/userguide/notification-how-to-event-types-and-destinations.html)

网页每 2 秒开始轮询任务，随后退避至 5 秒；页面隐藏时降低频率，结束后停止。请求失败保留最后已知状态并提示重试，不将轮询失败改写成处理失败。用户展示和下载 URL 初始有效期 60 秒，只有通过当前权限检查才签发；它是短期 bearer 凭证，有效期内持有者仍可使用，不承诺实时撤销。worker 的对象读取 URL 则在实际跨云调用前签发，初始有效期 900 秒且不得超过运行时凭证寿命，覆盖冷启动和完整处理预算；队列、Outbox 和数据库只存对象引用。浏览器上传授权初始为 600 秒，过期后先核对对象是否已完成，再给同一受控会话重新授权。数据库和邮件保存稳定页面链接，禁止长期保存签名 URL。

可恢复请求错误首先在当前 worker 的总期限内做最多 2 次受控退避重试；达到期限则明确失败或过期。SQS 的长可见性超时用于容忍基础设施故障，不作为正常交互重试时延。用户主动重试时创建新的 attemptId 并使旧尝试失效；尚有效的查询素材可复用，已过期或终止并清理的查询必须重新上传。迟到消息只确认并退出，不能重建已清理素材。

### API 契约和错误处理

所有业务端点位于 `/api/v1`。写操作接受 Idempotency-Key，按当前用户、端点和请求摘要绑定；同键同请求返回原操作，同键不同请求返回冲突。异步操作返回 202、jobId 和 statusUrl。错误格式固定为 code、message、requestId、retryable、details，details 不含凭证和内部异常堆栈。

| 接口 | 主要输入和输出 | 权限与关键约束 |
| --- | --- | --- |
| POST /uploads | 文件名、类型、字节数、SHA-256、可见性、目击时间；返回 uploadId、mediaId、上传授权 | owner 取 token；重复返回已有本人媒体 |
| POST /uploads/{id}/complete | 确认上传；返回处理任务 | 校验对象及会话；重复提交安全 |
| GET /jobs/{id} | 当前阶段、进度、结果引用、可理解错误 | 仅任务所有者 |
| GET /media 与 GET /media/{id} | 分页图库和详情 | 私有仅本人；公开仅登录用户 |
| POST /media/{id}/access | 原图、缩略图或视频的短期 URL | 每次先鉴权；严格限定该媒体对象 |
| POST /search/tags | minimumCounts、时间、类型、游标 | 所有条件 AND；只返回 READY 与有权访问记录 |
| POST /search/thumbnail | 系统已知 thumbnailUrl | 解析映射后鉴权，绝不请求任意外部 URL |
| POST /query-jobs | type 为 file 或 pet；照片或视频元信息、描述、时间 | 先经过第二云 Cognito 验证；返回临时上传或查询任务 |
| POST /query-jobs/{id}/complete | 临时文件上传完成 | 进入查询处理；无媒体入库或通知 |
| GET /query-jobs/{id} | 物种查询或寻宠结果及清理状态 | 仅发起用户，结果短期有效 |
| POST /media/tags | urls、tags、operation 为 1 或 0 | 先完整校验权限，再执行；逐项报告运行结果 |
| POST /media/delete | urls；返回批量删除任务 | 仅本人；202 不等于已删完 |
| GET 与 POST /subscriptions | 查询或保存标签订阅 | 邮箱取已验证账号；UI 显示邮件确认状态 |
| DELETE /subscriptions/{id} | 取消指定订阅 | 已取消再次调用安全 |
| POST /chat/sessions 与 POST /chat/messages | 建立会话、提交文本；返回 Lex 消息与结果卡片 | 会话绑定服务端可信 sub，所有查询复用同一权限层 |

标签查询示例请求为 `{"minimumCounts":{"feral_pig":1,"cane_toad":3},"limit":20}`；批量标签示例为 `{"urls":["<系统媒体URL>"],"tags":["ginger"],"operation":1}`。输入显示名称与规范标签的转换在契约中列出，不能由各页面各自猜测。

401 表示缺失、无效或过期身份；403 表示明确无权执行操作；404 用于不存在或不宜暴露存在性的私有资源；409 表示版本或幂等冲突；413 表示超限；422 表示无法处理的输入；429 表示限流；503 表示依赖暂时不可用。空搜索使用 200 加空列表，不能用空列表掩盖后端错误。

缩略图反查和批量 URL 输入仅接受已知服务域名与已登记对象路径，兼容刷新前后的签名查询参数。直接取第三方 URL、任意 bucket 或任意本地文件路径均不属于接口能力。

SNS 路由由应用层选择当前可访问且匹配的用户主题，邮件只包含稳定应用链接和最少必要信息。一个人同时订阅多个匹配标签时，同一媒体版本合并为一封。SNS 确认是邮件通道授权，Cognito 邮箱验证不能自动替代它；UI 需要分别显示状态。

通知键定义为 subscriberId、mediaId、recordVersion 和 eventType 的组合。发送前再次核查订阅、可见性和删除状态，避免队列延迟泄漏。SNS Standard 加邮件不能保证严格 exactly once；对已确认发布成功的事件不重发，发布结果不确定时标记 UNKNOWN 并核查，避免盲目再次 Publish。验收要证明应用事件重放不会导致重复发布，同时记录服务层交付边界。

Lex 会话由后端生成并绑定 Cognito sub，保存 sessionId、ownerSub 和过期时间。前端提交的 userId 或 sessionAttributes 只作为不可信输入；fulfillment 根据服务端会话绑定恢复身份。API Lambda 的 RecognizeText 权限限定 bot alias，fulfillment Lambda 调用许可限定 Lex 资源；轮换用户后清除旧聊天结果。

### 部署顺序和回退办法

部署脚本按下面的顺序执行，每一步先检查上一步输出，发生错误停在当前阶段并保留日志。

1. 确认 A2 项目、账单条件、AWS 主体、区域、权限和本地依赖。记录部署前资源清单，避免覆盖其他课程项目。

2. 创建 AWS 私有存储、表、Standard SQS 与 DLQ；创建 GCP 模型桶、Artifact Registry 和必要服务 API。为每条队列配置来源策略。

3. 创建或引用 AWS 执行角色、GCP invoker 与 runtime 服务账号及 WIF。先准备能部署但不开放匿名调用的 Cloud Run。

4. 上传不可变模型资源和容器，部署推理服务；验证健康、契约、允许角色调用和错误身份拒绝。

5. 部署 Cognito、业务 API、中间件、CORS 和两用户测试。CORS 仅列开发和正式前端 origin，不能用通配配置替代授权。

6. 部署预处理、推理、Outbox、清理和通知函数；确认函数可消费队列后再启用 S3 通知，先上传一张可控测试图片。

7. 接入视频、查询和寻宠，完成临时素材清理；配置 Lex fulfillment 的资源权限后，build locale、发布 bot version 与 alias，再接聊天 UI。

8. 部署前端、创建专用测试订阅并由邮箱持有人确认；执行真实 smoke。保存资源 ID、镜像 digest、manifest 版本和配置摘要。

9. E24 通过后冻结 demo 配置，保留上一版本镜像与模型 manifest。报告引用这份资源和版本清单。

每次发布先对专用测试账号与素材执行 smoke，通过后再作为默认版本。模型回退切回上一个兼容 manifest，Cloud Run 回退到已验证 revision，Lambda 回退到已验证包或版本；schema 变更采用兼容性新增字段，首版避免不可逆迁移。回退不删除用户数据，已执行的删除也不能靠代码回退恢复。

DLQ 配置自动转移前先采用至少 5 次接收作为基础设施故障初值；函数 timeout 与 visibility 保持安全比例，失败条目明确区分业务失败和投递失败。恢复脚本只重新驱动指定 jobId 或本轮测试资源，不能一键无差别重放所有失败队列。[Lambda 与 SQS 配置](https://docs.aws.amazon.com/lambda/latest/dg/services-sqs-configure.html)
